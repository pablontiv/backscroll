# OMP input evidence (2026-10-12, native v3 boundary)

## Evidence and scope

Issue #124 selects a dedicated `omp` decoder and `source = "session"`, not a Pi
alias, generic selector, new source value or schema migration. The integration
brief was read from `/tmp/omp-support-124.md`; that external coordinator artifact
is not a repository artifact. All retained JSONL fixtures are synthetic and
sanitized; no private transcript values, credentials or live session IDs were
copied into this change.

Structural verification used installed OMP **18.10.3** sources under
`@oh-my-pi/pi-coding-agent`, plus sibling `pi-ai` and `pi-utils` packages:

| Local package file | Verified boundary |
| --- | --- |
| `pi-coding-agent/src/session/session-entries.ts` | `CURRENT_SESSION_VERSION=3`; fixed-width 256-byte `title` slot; `SessionHeader` owns `id`, `timestamp`, `cwd`; message entry `id`, `parentId`, timestamp and native message |
| `pi-ai/src/types.ts` | Text blocks use `text`; thinking blocks use **`thinking`**, not Pi's `text`; tool calls use `id/name/arguments`; tool results use `role="toolResult"`, `toolCallId/toolName/content/isError/details`; user attribution and synthetic flag are explicit |
| `pi-coding-agent/src/tools/bash.ts` | Native tool name `bash`; numeric exit code lives in result `details.exitCode` |
| `pi-utils/src/dirs.ts` | Canonical `.omp/agent` directory; agent override/profile/XDG paths require explicit configuration rather than assuming the canonical preset covers them |

The coordinator brief supplies the explicit `details.__interrupted=true`
boundary. Only that structured flag is consumed; aborted assistant stop reasons
and stored interrupt-like text do not prove a user interruption. This is a
native filesystem v3 compatibility boundary, not a census of all OMP versions
or SQL/Redis backends. No provider configuration or transcript is modified.

## Sanitized oracle

`tests/fixtures/omp-v3.jsonl` is constructed from the verified structural types,
not copied from sessions or generated by the production parser. It includes a
title before the header, explicit human/synthetic/agent/missing attribution,
developer and assistant content, readable thinking, and a Bash result before
its call. `parentId` deliberately names unrelated branch ancestry. Negative
markers cover admin/derived/unknown/special-role records, images, encrypted and
redacted content, signatures/provider payloads, arbitrary details, invalid
message timestamps, missing entry identity and malformed neighboring JSON.

The independent expected row/origin/metadata table in `TestOMPReaderNativeV3`
checks physical order, all supported origins, opt-in reasoning and raw metadata.
`TestOMPReaderRawMetadataAndEcho` uses a 5,000-rune output to prove that numeric
exit/error/interruption signals and ID-paired echo provenance survive the
4,000-rune serializer cap. Non-Bash numeric details do not become exit evidence.
`TestOMPReaderStrictBoundary` rejects pre-v3, absent/duplicate/invalid headers,
preserves valid neighbors and proves cross-session entry ID namespacing.

## RED/GREEN boundary and verification ownership

The baseline has no `omp` runtime registration or shipped OMP preset; a native
OMP manifest therefore has no decoder. No executable baseline RED test was run:
the dispatched task explicitly prohibited builds/tests/formatters until all
implementation edits were complete. That absence must not be reported as an
observed RED run. Tests were authored before the reader implementation.

The final targeted reader/input-config/CLI test pass is the GREEN gate. In
addition to the unit oracle, it exercises:

- The shipped canonical preset: direct bucket files only, nested child/root
  files excluded, symlinks off, missing root safe, no Pi root alias.
- Native registration, real command-startup sync, source/path/role/date/project
  filters, separate explicit tool retrieval, excluded markers and reasoning
  opt-in in a fresh isolated HOME/config/database.
- Persisted parser-backed origins and native tool metadata in SQLite.
- Unchanged sync, append preserving UUID **and physical database row ID**,
  source deletion and non-destructive `rebuild` retaining perennial recall.
- The shipped and living documented OMP TOML examples at the command boundary.

Installer tests assert OMP fresh-copy bytes, existing-manifest preservation and
explicit force-refresh replacement in Unix and PowerShell surfaces. PowerShell
execution is environment-dependent and must not be claimed without a runtime.
